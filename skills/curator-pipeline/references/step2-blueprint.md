# Step 2 — 构建策展蓝图

> 目标：把 Step 1 锁定的方向，扩展成可执行的章节结构 + P0/P1/P2 增值点 + 卖点切片 + 关键词布局。
> **失败要点**：找不到 ≥2 个整理切面 → 红线，原素材撑不起策展。

## 0. 读规范

每次都重读：
- `/root/xhs-shop/memory/CURATOR_STYLE.md`
- `meta.json`（确认上下文）

## 1. 必交付清单（缺一不可）

按以下顺序产出，全部交付前不能进入 Step 3。

### 1.1 同类产品调研（微创新前提）

去小红书 / Reddit / 行业社群里看 ≥3 个同类产品在卖什么。简表：

```
| 同行 | 卖点 | 单价 | 销量 | 弱点 |
|------|------|------|------|------|
| A | xxx | 9.9 | 200+ | 案例少 |
| B | xxx | 39.9 | 50+ | 无可落地物 |
```

如果完全找不到同类产品 → 警示"赛道未验证，是先驱还是先烈，请用户确认"。

### 1.2 微创新点（必须 ≥1）

"同行做 X，本品做 X + Y + Z"。Y/Z 是同行没做、买家会买单的部分。

例：同行卖面试题（30 道）→ 本品卖面试题（60 道）+ 回答思路 + 面试官隐藏考点 + 回答示例。

### 1.3 3 个章节结构变体（让用户选）

不能是"什么是 X / 为什么重要 / 怎么用"老三段。每个变体写：
- 章节标题列表（6-10 章）
- 这个结构的"叙事动线"是什么（按时间线？按场景？按问题难度？）

### 1.4 ★ 增值点 + P0/P1/P2 标记

为用户选定的章节结构里的每一章，列出 ★ 增值点：

```
章节 3：xxx
  ★ A：xxx     [P0] —— 因为这是买家最容易追问的点
  ★ B：xxx     [P1] —— 锦上添花，单层搜索即可
  ★ C：xxx     [P2] —— 用原文素材即可，不搜索
```

**P 级定义**：
- **P0**：必须三层来源（起源 / 原理 / 实证）。预算高（约 3 次搜索/★）
- **P1**：单层搜索（找 1 个权威来源即可）
- **P2**：原文 + 常识，不搜索

**预算上限**：每份 PPT 总 P0 数 ≤ 5，P1 数 ≤ 10。超过预算 → 让用户砍优先级。

### 1.5 卖点切片清单

每章问自己："这章拿出来能不能独立成一篇引流小红书笔记 hook？"
列出所有 ✅ 的章节作为卖点切片，标注主 hook（最容易引流的那个）。

### 1.6 关键词布局

调研小红书搜索高频词（用户描述场景 / 同行标题里的词）。列：
- 主关键词（必须出现在 PPT 标题 + 小红书笔记标题前 5 字）
- 副关键词（章节标题用）
- 长尾关键词（小红书文案备选）

### 1.7 明示反面

"本策展刻意没做 X、Y、Z，因为：..."
作用是让用户看清边界，避免后续要求加入 X 时回到 Step 2 重来。

### 1.8 风格基调

继承 Step 1 AI 初印象 + 用户纠偏后的语言/视觉风格。一句话：
"本次策展风格：xxx（学术/口语/故事性/极简）配 xxx（案例/对比表/步骤图解）"

## 2. 检查红线

走完 1.1-1.8 后：
- 🔴 整理切面 < 2 个？→ STOP，报"原素材不支持策展深度"
- 🔴 无微创新点？→ STOP，让用户决定换素材或换角度
- 🔴 章节结构变体仍是"什么是/为什么/怎么用"老三段？→ 重写

## 3. 写入 meta.json

```json
{
  "priority_grading": { "p0_count": <N>, "p1_count": <N>, "p2_count": <N> },
  "step_progress": { "current_step": 3, "completed_steps": [1,2] }
}
```

把蓝图保存到 `products/<slug>/curation.md`（追加，不覆盖 Step 1 内容）。

## 4. 确认门 ✅

"蓝图已出。同类产品 N 个、微创新 ≥1 点、章节结构选 X、★ 增值点 P0/P1/P2 分布 X/Y/Z、卖点切片 N 个、关键词 N 个、明示反面 N 项。可进入 Step 3 分章填充吗？"

Fast mode：本步仍需确认（属于 3 个核心确认门之一）。
